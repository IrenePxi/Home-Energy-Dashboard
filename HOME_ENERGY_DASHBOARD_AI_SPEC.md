# Home Energy Dashboard – Panel-by-Panel Data Guide

## Overview table (one row per panel)

| Panel name | What it shows (short) | Where the data comes from | Data type category |
|---|---|---|---|
| Real-time Power Flow | Current household electrical state (PV, grid, battery, load) | House/local telemetry feed (live) | Measured ground truth |
| Electricity Price (Actual vs Predicted) | Electricity price time series labeled **Actual** and **Predicted** | Actual: public published electricity price data; Predicted: local/model-generated price forecast | Public known data (Actual) + Model prediction (Predicted) |
| PV Power Forecast | PV generation forecast time series | Local/model-generated PV forecast using weather inputs and local PV data | Model prediction |
| CO₂ Forecast | CO₂ intensity prognosis time series | Public CO₂ prognosis/prognostic dataset | Public forecast/prognosis |
| Weather Forecast | Temperature time series (weather outlook) | Public weather forecast/archive source | Public forecast/prognosis |
| Natural Gas Price | Natural gas balancing price history | Public gas price dataset | Context data |
| Smart Scheduling | Suggested device run window(s) + computed totals (energy, cost, CO₂ estimate when available) | Computed by the app from electricity prices, device settings, and (optionally) CO₂ prognosis | Optimized/computed result |

## Panel: Real-time Power Flow

- **What the chart shows**: Current household electrical state, including PV power, grid power, battery state of charge (SOC), battery power, and household load (phase components and a total).
- **Where the data comes from**: House/local telemetry feed delivered via MQTT topics into the dashboard.
- **Data type category**: Measured ground truth.
- **Time range / horizon**: Current (live “now” values).
- **Time resolution**: Live update cadence; the UI refreshes about every ~2 seconds when live updates are enabled (values are “latest sample” rather than a historical time series).
- **Input data used**:
  - Latest MQTT values for: PV power, grid power, battery SOC, battery power, load per phase, and total load.
- **Output value(s) shown**:
  - PV power
  - Grid power
  - Battery SOC
  - Battery power
  - Load per phase and/or total load
- **Unit(s)**:
  - Battery SOC: percent (%)
  - Power values: shown as watts (W) in the live dashboard view
- **Value meaning**:
  - A snapshot of the home’s current electrical conditions: generation (PV), consumption (load), grid exchange, and battery state/power.
- **Main purpose**:
  - Provide immediate “what is happening right now” visibility into household energy flows.
- **Notes / limits**:
  - Live values can become stale if the telemetry feed disconnects.
  - Sign conventions (e.g., whether positive grid power means import vs export) depend on the telemetry source; the dashboard displays the values but does not universally enforce sign meaning.

## Panel: Electricity Price (Actual vs Predicted)

- **What the chart shows**: Electricity price time series with two labeled series: **Actual** (published) and **Predicted** (model forecast).
- **Where the data comes from**:
  - Actual: public electricity price dataset (published day-ahead/spot prices).
  - Predicted: locally produced forecast generated by the app’s price prediction pipeline.
- **Data type category**: Public known data (Actual) + Model prediction (Predicted).
- **Time range / horizon**:
  - Actual: near-term published window (typically today and tomorrow, as available).
  - Predicted: multi-day outlook (produced as an hourly series for multiple future days; the app produces ~4 days of hourly predictions from today).
  - The panel may also show a recent lookback (recent past) alongside the forward range for context.
- **Time resolution**: Hourly.
- **Input data used**:
  - Actual price series for the relevant price area (e.g., DK1).
  - Weather/time features used by the prediction pipeline (internal to the app’s forecast generation).
- **Output value(s) shown**:
  - Spot price (DKK/kWh) for timestamps, labeled by source (**Actual** vs **Predicted**).
  - (If displayed in the UI) model error metrics loaded from a local metrics file.
- **Unit(s)**:
  - Price: DKK/kWh.
- **Value meaning**:
  - **Actual**: known published price values for their timestamps.
  - **Predicted**: forecasted price values for future timestamps produced by a local model.
- **Main purpose**:
  - Present known prices and a forward-looking estimate of prices in the same view.
- **Notes / limits**:
  - Predicted values are a model output and can deviate from realized prices.
  - The panel distinguishes Actual vs Predicted explicitly; they should not be treated as equally reliable for the same timestamp when both exist.

## Panel: PV Power Forecast

- **What the chart shows**: Forecast PV generation time series for the household/system.
- **Where the data comes from**: Locally generated PV forecast produced by the app using weather inputs and local PV data/modeling.
- **Data type category**: Model prediction.
- **Time range / horizon**: Multi-day forecast; the app produces ~3 days ahead as an hourly series starting from today.
- **Time resolution**: Hourly.
- **Input data used**:
  - Weather inputs (public weather data) used as drivers/features.
  - Local PV history/training data (used by the forecast pipeline).
- **Output value(s) shown**:
  - PV forecast series (e.g., a corrected PV power forecast over time).
- **Unit(s)**:
  - PV power forecast is shown in kW in the PV forecast panel.
- **Value meaning**:
  - Expected PV generation power over future hours according to the app’s PV forecasting pipeline.
- **Main purpose**:
  - Provide an outlook for expected solar generation over the next few days.
- **Notes / limits**:
  - PV forecasts are weather-sensitive; forecast error can increase with changing cloud cover/conditions.
  - Ensure unit interpretation is consistent when comparing PV forecast to any live PV telemetry (which may be displayed in W in the live panel).

## Panel: CO₂ Forecast

- **What the chart shows**: CO₂ emissions intensity prognosis as a time series (e.g., grams CO₂ per kWh).
- **Where the data comes from**: Public CO₂ prognosis/prognostic dataset fetched by the app (external source).
- **Data type category**: Public forecast/prognosis.
- **Time range / horizon**: Multi-day prognosis; the app fetches up to ~96 hours ahead and charts from today onward.
- **Time resolution**: 5-minute resolution (prognosis points).
- **Input data used**:
  - CO₂ prognosis time series for the configured area (e.g., DK1).
- **Output value(s) shown**:
  - CO₂ intensity (gCO₂/kWh) over time.
- **Unit(s)**:
  - gCO₂/kWh.
- **Value meaning**:
  - Expected carbon intensity associated with grid electricity over time according to the external prognosis dataset.
- **Main purpose**:
  - Provide a time-varying carbon intensity outlook as a contextual planning signal.
- **Notes / limits**:
  - It is a forward-looking prognosis; values can change as the source updates.

## Panel: Weather Forecast

- **What the chart shows**: Temperature time series (weather outlook), typically including a short lookback and a forward forecast window.
- **Where the data comes from**: Public weather archive + forecast source (queried by the app).
- **Data type category**: Public forecast/prognosis.
- **Time range / horizon**: Recent past (e.g., starting yesterday) through multiple days ahead (the app fetches roughly up to ~4 days forward for display).
- **Time resolution**: Hourly.
- **Input data used**:
  - Weather time series from the public weather source (temperature, and potentially additional weather variables used by the app’s models).
- **Output value(s) shown**:
  - Temperature over time (and any other weather series included by the panel, if enabled).
- **Unit(s)**:
  - Temperature: °C.
- **Value meaning**:
  - Weather conditions over time as provided by the public source (mix of recent archive and forecast).
- **Main purpose**:
  - Provide weather context for the household and for model-driven panels (e.g., PV/price forecasting inputs).
- **Notes / limits**:
  - Availability depends on the upstream weather API; the app may cache results and may show stale data during outages/rate limits.

## Panel: Natural Gas Price

- **What the chart shows**: Natural gas balancing price history (recent days/weeks).
- **Where the data comes from**: Public gas price dataset fetched by the app (external source).
- **Data type category**: Context data.
- **Time range / horizon**: Historical window; the panel typically displays recent weeks (the UI commonly shows about the last ~35 days).
- **Time resolution**: Daily.
- **Input data used**:
  - Gas balancing price time series (daily values) from the public dataset.
- **Output value(s) shown**:
  - Gas price series over recent dates.
- **Unit(s)**:
  - As provided by the dataset (commonly shown as DKK per kWh in the app’s plotting/column naming).
- **Value meaning**:
  - A market context series (not household telemetry), shown for background reference.
- **Main purpose**:
  - Provide broader market context alongside the electricity-focused dashboard panels.
- **Notes / limits**:
  - This panel is historical context; it does not represent household consumption or a household sensor.

## Panel: Smart Scheduling

- **What the chart shows**: Suggested run window(s) for selected devices, plus computed totals such as expected energy use, expected cost, and (when available) an estimated CO₂ impact for the scheduled run.
- **Where the data comes from**: Computed by the app from:
  - electricity price time series,
  - user-selected device parameters (power, duration),
  - and optional CO₂ prognosis data for the same time interval.
- **Data type category**: Optimized/computed result.
- **Time range / horizon**: A fixed scheduling window ending at a deadline (shown in the app as “Today 00:00 → Tomorrow 06:00”), with the optimization effectively considering future start times from “now” up to the deadline.
- **Time resolution**: Price series is treated as hourly for cost averaging; scheduling start candidates follow the price series timestamps used by the optimizer.
- **Input data used**:
  - Device inputs: duration (hours) and power (kW) for each selected device.
  - Electricity price series (Actual + Predicted where applicable).
  - CO₂ prognosis series (if provided/available for the scheduled interval).
- **Output value(s) shown**:
  - Suggested start time and end time for each selected device (best interval found).
  - Estimated energy (kWh) for the run (computed from power × duration).
  - Estimated total cost (DKK) for the run (computed from average spot price × kWh).
  - Estimated CO₂ impact (grams) when CO₂ data covers the interval (computed from mean gCO₂/kWh × kWh).
- **Unit(s)**:
  - Power: kW (device parameter)
  - Duration: hours
  - Energy: kWh
  - Price: DKK/kWh
  - Cost: DKK
  - CO₂: grams (g)
- **Value meaning**:
  - A best-cost run window chosen by the app’s scheduler over the allowed timeframe, with derived totals for energy/cost and optional CO₂ estimate.
- **Main purpose**:
  - Provide a concrete suggested run time for flexible devices based on the available price series, plus summary totals for what that run would cost/consume.
- **Notes / limits**:
  - The schedule is computed from the available price series; if a future period is covered by predicted prices, the optimizer can still use it, but the input is a forecast.
  - CO₂ impact is only shown when the CO₂ prognosis covers the chosen interval; partial/missing coverage may result in no CO₂ estimate.
